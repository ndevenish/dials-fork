## Project Overview

DIALS (Diffraction Integration for Advanced Light Sources) is scientific software for X-ray crystallography data processing. It's a Python (3.11+) and C++ project that is part of the cctbx/libtbx ecosystem, with ~30 Boost.Python extension modules and 94 command-line tools.

## Build Commands

```bash
# Bootstrap install (creates full development environment)
git clone https://github.com/dials/dials modules/dials
python modules/dials/installer/bootstrap.py

# Activate environment (required each session)
source <root>/dials

# Rebuild after code/dependency changes
cd <root>/build && ninja
```

## Testing

```bash
# Full test suite
pytest tests/
libtbx.pytest --regression

# Single test file and others follow normal pytest commands.
```

Test data is provided by the `dials-data` package. Tests using it require the `dials_data` fixture.

## Architecture

### Source Layout (`src/dials/`)

- **`algorithms/`** — Core scientific algorithms: indexing (FFT1D, FFT3D, RealSpaceGridSearch, PinkIndexer), integration (Bayesian, sum, profile fitting), refinement, scaling (physical/KB/array models), spot finding, background correction, profile modeling
- **`command_line/`** — 94 CLI tools (e.g. `dials.find_spots`, `dials.index`, `dials.integrate`, `dials.scale`). Each file has a `run()` function; entry points are auto-generated by `build.py`
- **`model/`** — Data model classes (ExperimentList, detector, beam, crystal, etc.)
- **`array_family/`** — Flex array data structures (wrapping C++ flex module)
- **`extensions/`** — Plugin system for algorithm backends (background, centroid, scaling models, profile models, spotfinder thresholds), registered via setuptools entry points
- **`util/`** — Shared utilities
- **`nexus/`** — NeXus file format support

### Key Dependencies

DIALS depends on the cctbx ecosystem: **dxtbx** (diffraction experiment toolbox), **cctbx** (computational crystallography), **scitbx** (scientific algorithms), **libtbx** (build/configuration). These are separate repositories but tightly coupled.

### C++ Extensions

C++ code lives alongside Python in `src/dials/` subdirectories. Built via CMake (C++14 standard) into Boost.Python extension modules. Configuration in the top-level `CMakeLists.txt`.

## Contributing Conventions

- PEP8 naming (snake_case variables, CamelCase classes)
- Google-style docstrings for new code
- Avoid `from module import *`
- Avoid single-function classes; prefer plain functions
